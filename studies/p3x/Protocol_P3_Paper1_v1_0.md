## 1. Scope and relation to Paper 2
- Paper 1 studies the algorithms only. All objectives are evaluated on the **true values** (world T of the earlier studies): no uncertainty, no evidential quantities, no observation strategies. Uncertainty is Paper 2.
- Problem [INHERITED, verified in `evaluate` of `p1m.py`]: Solomon-derived home health care instances, six scenarios (S4-RC101, S5-RC101, S4-R101, S5-R101, S4-C101, S5-C101). **Decision**: one team per patient (a vector of team indices, restricted by the mask M of allowed teams). **Visit order**: each team visits its patients in patient-index order; arrival times follow from that fixed order (waiting until the window opens). The visit sequence is **not** optimised. The problem is therefore an **assignment-and-scheduling problem with a fixed visit order**, not an integrated routing problem; the paper must not be titled or described as routing. Integrated routing and scheduling (sequence decisions) is declared future work.
- Objectives [INHERITED, all minimised, in [0,1], reference point (1.2, 1.2, 1.2), exact 3D hypervolume], to be stated with their exact formulas in the paper:
  - f1 = min(1, total travel time / (day_end x number of teams)), where the travel time of a team is the sum of the entries of the matrix D along its route, including the return to the depot (verified in `evaluate`: only travel is summed; waiting and visit durations are not). **Units**: D is the travel-time matrix (arrival = departure + D) in the same time units as `day_end`, so f1 is dimensionless: the share of the available team time spent travelling. (The docstring of `evaluate` says "route length"; the paper uses "travel time".) **Clipping**: the min(1, .) can make very poor solutions indistinguishable; in the technical pilot data of P2 step 2 (seeds 3800-3809, 9 640 front points) the largest f1 was 0.962 and none reached 0.999, so the clip was not active on any final-front point (descriptive observation; to be re-checked on the P3 technical seeds and reported);
  - f2 = 1 - mean over patients of [0.7 x (0.5 x time-window fit + 0.3 x preference + 0.2 x punctuality) + 0.3 x satisfaction of the team for the care type];
  - f3 = 1 - clip01(0.3 x workload balance + 0.7 x mean over patients of the minimum adequacy of the team over required skills - 0.2 x overload share).
  In Paper 1 the satisfaction and adequacy values are the true values (no uncertainty).
- Overlap rule [P]: Paper 1 uses **new experiments on new seeds**. The world-T result of P2 step 2 (NSGA-II standard better than QGA2 by about 0.13 hypervolume; QGA2 better than non-elitist NSGA-II by about 0.033) is cited as preliminary evidence and motivation, not re-reported as a result of Paper 1. The P2 step 2 data stay with Paper 2.

## 2. Question and framing [P]
Question: at equal evaluation budget, can QGA2 compete with classical Pareto-based evolutionary algorithms, and which design component explains the difference?
Framing proposed: **method + mechanism study**. P2 step 2 suggests that the QGA2 weakness comes from non-elitist replacement. We therefore (i) add an elitist QGA2 and (ii) test the effect of the variation operator and of elitism in a 2x2 factorial design. All outcomes, including a negative one, are reported.

## 3. Algorithms [P]
Common: POP = 40, budget = 40 + 150 x 40 = 6 040 calls to `evaluate()` for every algorithm in the main comparison; same mask M of allowed teams; same decoder; same initial population for a given instance and seed. **Definition of "same initial population"**: the shared object is the set of 40 decoded assignments x produced by the inherited `init_pop` (angles drawn on the "init" stream, decoded on the "evo" stream). The QGA variants start from the angles theta that generated those x (so no conversion from x to angles is needed); NSGA-II variants start from the same x. Test: generation-0 assignments are identical in the four core algorithms.

2x2 factorial core:
| | Generational replacement | Elitist replacement |
|---|---|---|
| Q-bit rotation (two amplitudes, P = sin^2 theta) | QGA2 [INHERITED, unchanged] | **QGA2-E** (new) |
| Crossover + mutation | NSGA-II paired (no merge) [INHERITED definition; named "non-elitist (generational) NSGA-II variant" in the paper, "NSGA-II standard" being the elitist version] | NSGA-II standard [INHERITED definition] |

- **QGA2-E** (specified):
  - An *individual* is the record (theta, x, r, f): the angle array theta, the decoded assignment x, the decoding draws r = (ux, ur) (arrays of shape n_p x n_t and n_p, the two inputs of `collapse_r` besides theta and M) and the objective vector f. **Invariant: an individual entering or leaving survival always carries the theta and the draws that generated its x; theta, x and r are never recombined or selected separately.** Storing r costs n_p(n_t + 1) numbers per individual and makes the invariant test exact: collapse_r(theta, M, ux, ur) must return x.
  - Generation 0: 40 individuals from the common initial population, evaluated (40 calls).
  - Each generation: let *best* be the first individual of the first non-dominated front of the current population in its current (post-survival) order, the same rule as QGA2. Child i is built from parent i: theta_i is rotated toward *best* (same step, same bounds and mask as QGA2), then decoded to x'_i with the draws of the child stream; the child keeps its rotated theta'_i. The 40 children are evaluated (40 calls).
  - Survival: `select_next` (non-dominated sort + crowding) applied to the 80 (theta, x, f) records (40 parents then 40 children, in that order), returning 40 indices; the corresponding records are kept unchanged, in the order returned. Ties are resolved by `select_next`'s own deterministic order (test: same input gives the same indices). Duplicate decoded assignments are **not** merged: two records with identical x but different theta are both eligible; the output front removes duplicate objective vectors at the end only.
  - Output: first non-dominated front of the final population, re-evaluated in the true world as in the earlier studies (identical to the inherited front procedure).
  - No other change from QGA2; budget 40 + 150 x 40 = 6 040.
- **Consistency of the 2x2 replacement rule**: generational = the next population is the 40 children only (survival via `select_next` on the 40 children, which reorders them and drops nobody; the order returned is the population order, and it determines *best* (first individual of the first front) and the parent-child index pairing in the next generation, identically in QGA2 and NSGA-II paired); elitist = survival on parents + children (80 to 40). The same function, the same tie rule and the same record handling are used in all four cells.
- QGA2-A (descriptive): QGA2 dynamics unchanged plus an external archive of all non-dominated solutions seen; output = archive. Isolates the effect of keeping the best front without changing the search.
- Further baselines (secondary, not in the confirmatory family):
  - MOEA/D with the same budget (decomposition, Tchebycheff);
  - **scalarised pair (like-for-like classical GA versus QIGA)**: (i) weighted-sum classical GA (crossover + mutation, elitist replacement) and (ii) weighted-sum QGA2 (same Q-bit rotation and decoding as QGA2, scalar fitness, rotation toward the best scalar individual, elitist replacement), each run for 15 weight vectors w = (i, j, k)/4 with i + j + k = 4, i, j, k integers >= 0 (the 15 compositions; objectives are already in [0,1], so no further normalisation). Budget per weight vector: 40 + 9 x 40 = 400 evaluations (total 6 000, 40 below the main budget; declared). Scalar fitness = w1 f1 + w2 f2 + w3 f3 (lower is better); ties in scalar fitness are broken by the lowest population index; the best of a weight vector is the lowest scalar fitness in its final population (ties: lowest index). Output: non-dominated set of the 15 final best individuals, evaluated in the true world as in the earlier studies;
  - random search with the same budget (floor);
  - exact epsilon-constraint on small instances only if the feasibility check in the pilot shows it is tractable [TO FIX].
- Tuning (rule written here, before any tuning): every tuned algorithm gets the same effort, 3 parameter sets, on the 20 tuning seeds (4210-4229) in world T. Criterion = mean over the tuning seeds of the per-seed mean over the six scenarios of the hypervolume of the algorithm's output. A tuning seed counts only if all six of its scenarios are feasible. The set with the highest criterion is chosen; if its criterion exceeds that of the a priori set by less than 0.001, the a priori set is kept. No other criterion, no second pass, no added set.
  - QGA2, QGA2-E and weighted-sum QGA2 (each tuned separately; QGA2-A uses the QGA2 value): rotation step delta in {0.025 pi, 0.05 pi, 0.1 pi}; a priori 0.05 pi.
  - NSGA-II standard: (p_c, p_m) in J1 = (0.9, 1/n_p) [a priori], J2 = (0.9, 2/n_p), J3 = (0.7, 1/n_p) (the P2 step 2 sets); NSGA-II paired inherits the chosen set, as in P2 step 2.
  - Weighted-sum GA: the same three sets J1-J3, a priori J1.
  - MOEA/D: neighbourhood size T in {5, 10, 20}, a priori 10 (p_c = 0.9 and p_m = 1/n_p fixed).
  - Random search: nothing to tune.
- Sensitivity to budget [descriptive]: the four core algorithms are repeated with 600 generations (budget 40 + 600 x 40 = 24 040 evaluations, about 4x) with the tuned parameters, **on the first 20 confirmatory seeds only** (4300-4319), because of cost (stated restriction, written before any result). Mean HV and the three primary contrasts are reported with bootstrap CI, without tests.

### 3.1 Operator specifications (all algorithms; evaluation always in world T through `evaluate()`; random streams are `rs(scenario, seed, name)` as in earlier studies)
- **Decoder** (QGA family): `collapse_r(theta, M, ux, ur)` [INHERITED]. Initial angles: pi/2-uniform-equivalent value asin(sqrt(1/n_t)) plus N(0, 0.02^2) noise on the "init" stream, clipped to [0, pi/2] and masked by M; initial draws on the "evo" stream. Rotation: for child i from parent i, s = best_onehot(1 - parent_onehot) - (1 - best_onehot) parent_onehot per (patient, team), theta' = clip(theta + delta s, 0, pi/2) masked by M [INHERITED from QGA2].
- **NSGA-II (standard and paired)** [INHERITED, implemented in `p2s2.nsga2`]: initial population = the common 40 assignments; each generation computes rank (non-dominated sort) and crowding distance (library `crowding_dist`, boundary points 1e9) of the current population; each of the 40 children is made by two binary tournaments (two indices drawn uniformly with replacement; lower rank wins; equal rank: larger crowding wins; equal crowding: coin flip from a dedicated tie stream); crossover with probability p_c: uniform, each gene taken from the first parent with probability 0.5, otherwise from the second; without crossover the child copies the first parent; mutation: each gene independently with probability p_m, replaced by another allowed team drawn uniformly (unchanged if there is none); survival by library `select_next` (fronts in order, crowding-distance truncation of the last front, deterministic): standard = 80 to 40; paired = the 40 children only. Output = first front of the final population.
- **QGA2** [INHERITED]: as in `p2s2.qga2_pop`; the population is reordered by `select_next` (40 to 40) at the start of each generation; children are decoded from the rotated parents in index order on the continuing "evo" stream.
- **QGA2-E**: as specified in this section 3 (records (theta, x, r, f)); the initial population is reordered by `select_next` (40 to 40) exactly as QGA2 does at its first generation, so that the first-generation children of QGA2 and QGA2-E are identical (test); afterwards each generation is: rotate toward best, decode on the continuing "evo" stream, evaluate, survival on 80 to 40.
- **QGA2-A**: the QGA2 run itself, plus an archive updated after every evaluated batch; the archive keeps the non-dominated set of all objective vectors evaluated so far, one record per distinct objective vector (the first seen); output = archive assignments, re-evaluated.
- **Weighted-sum GA** (for each of the 15 weight vectors w): population 40 from the common initial assignments; each generation: 40 children by binary tournament on the scalar fitness (lower wins, equal: lower index) followed by the NSGA-II crossover and mutation operators; the 80 parents + children are sorted by scalar fitness (stable, lower index first among equals) and the best 40 are kept; 9 generations; stream names include the weight index. Result of w = the lowest scalar fitness of the final population. Output = non-dominated set of the 15 results, re-evaluated.
- **Weighted-sum QGA2**: the QGA2 rotation and decoder; the initial population is the common one; best = lowest scalar fitness (equal: lower index); children from parent i; survival = best 40 of the 80 by scalar fitness (stable); 9 generations; child draws on a stream named with the weight index; result and output as above.
- **MOEA/D** (secondary): 45 weight vectors (Das-Dennis lattice, H = 8, w_k in {0, 1/8, ..., 1}, sum 1), Tchebycheff scalarisation g(x | w) = max_k w_k' |f_k(x) - z_k*| with w_k' = max(w_k, 1e-6) and ideal point z* updated online, neighbourhoods of T nearest weight vectors (Euclidean, ties by index); initial population = the 40 common assignments plus 5 further assignments drawn by the same initial-population procedure (the first 40 are identical by construction), assigned to the vectors in lexicographic order; steady-state: for each subproblem in index order, parents drawn uniformly from its neighbourhood with probability 0.9 and from the whole population otherwise, crossover/mutation as NSGA-II (p_c = 0.9, p_m = 1/n_p), at most 2 replacements among the neighbours (visited in a random order) whose g is not better than the child's; 133 generations; budget 45 + 133 x 45 = 6 030 evaluations (10 below the main budget; declared). Output = first front of the final 45 solutions.
- **Random search**: 6 040 assignments, each gene drawn uniformly among the allowed teams; output = non-dominated set of all 6 040.
- **Outputs and hypervolume**: every output set is re-evaluated through `final_front` (world T, unique non-dominated vectors) and its hypervolume is computed exactly against (1.2, 1.2, 1.2) with the library routine; HV = 0 for an empty set.

## 4. Hypotheses [P]
Primary family (3 two-sided paired Wilcoxon tests, Holm, alpha = 0.05), outcome = per-seed mean over the six scenarios of true-world hypervolume (HV = 0 for an empty set):
- H-3.1 elitist QGA2-E versus NSGA-II standard (variation operator effect under elitism);
- H-3.2 QGA2 versus NSGA-II paired (variation operator effect without elitism; **replication** of a difference seen in P2 step 2, now on new seeds);
- H-3.3 QGA2-E versus QGA2 (effect of elitism for the Q-bit algorithm).
The primary QGA variant is fixed in advance as QGA2-E; no variant is selected after seeing results.
Descriptive: all other pairwise differences with bootstrap CI (5 000 replicates, whole seeds), QGA2-A, MOEA/D, weighted-sum GA, random search, interaction of the factorial, defined per seed as Delta_int = (HV[QGA2-E] - HV[QGA2]) - (HV[NSGA-II standard] - HV[NSGA-II paired]), reported as mean with bootstrap CI and sign counts, descriptive and outside the Holm family, IGD+ against a pooled reference front built from all runs (rule declared in advance), runtime, convergence every 10 generations on the first 20 confirmatory seeds.
No equivalence margin: a non-significant result is not read as equivalence. A result where the classical algorithm wins is a result.
Effect sizes: for each primary contrast report the mean paired difference with its bootstrap CI, the median, the counts of positive, negative and zero differences, and the paired rank-biserial correlation, alongside the Holm-adjusted p-value.
**Interpretation rule (written in advance)**: QGA2-E differs from QGA2 by the replacement mechanism, not by the Q-bit search itself. A QGA2-E gain over QGA2 (H-3.3) supports "elitist replacement improves this Q-bit algorithm under these conditions"; it does not by itself show that quantum-inspired search is superior to classical genetic search. Superiority claims are limited to H-3.1 (elitist versus elitist) and, without elitism, H-3.2. If QGA2-E improves on QGA2 but remains below NSGA-II standard, that is reported as such. The paper does not claim to introduce QIGA to healthcare scheduling or to multiobjective scheduling in general.

## 5. Sample size and seeds [P]
- Pilot for sizing on technical seeds. **Interpretation of the formula**: n = ceil(((z_{1-alpha'/2} + z_{power}) x sd_up / delta)^2) is the normal-approximation sample size for detecting a mean paired difference of delta with a two-sided test at level alpha' = 0.05/3 (a conservative Bonferroni level for the three-test family; Holm is at least as powerful) and power 0.80: z = 2.394 + 0.842 = 3.236. sd_up is the 80 percent upper confidence bound of the paired-difference standard deviation from the pilot, sd_up = s sqrt((n_p - 1)/chi2_{0.20}(n_p - 1)); the largest value over the three contrasts is used. delta = 0.01 is a planning convention (not an established effect). The Wilcoxon test is not sized directly: a simulation check (1 500 resamples of the centred pilot differences centred at their median and then shifted by delta (a location shift under the Wilcoxon null; the choice of median rather than mean is [P]), Wilcoxon at 0.0167, smallest n of the grid giving power >= 0.80 for all three contrasts) replaces the formula when zeros exceed 3 percent or |skewness| exceeds 1 or excess kurtosis exceeds 3. The result is rounded up to {100, 150, 200, 300}; stop and report if n exceeds 300. A 10-seed pilot gives only a rough sd estimate, and the simulation reuses the pilot's empirical distribution, so it cannot make up for the pilot's weakness (stated limits). The result is a sample-size estimate based on the pilot, not a guarantee of actual power.
- Seeds, disjoint from all earlier ranges (3000-3919 and previously used technical ranges): technical tests and pilot 4200-4209; tuning 4210-4229; confirmatory 4300 to 4300 + n - 1 (at most 4599).
- **Order of phases (clarification)**: (1) technical tests at the a priori parameters on seeds 4200-4209 (plus the non-regression instances below); (2) tuning on 4210-4229, selecting the parameter sets with the rule of section 3; (3) pilot on 4200-4209 with the tuned parameters, which gives the sample size n; (4) SHA-256 freeze of this protocol, the code, the tuned parameters, the analysis script and the tests; (5) confirmatory run; (6) analysis, run once. The chosen parameters are recorded in `p3_tuned.json` before the pilot.
- Three distinct cases, never mixed: (a) **instance infeasibility** (a patient has no authorised team in mask M): the instance is infeasible for every algorithm; the whole seed is excluded for all algorithms (non-differential), and the run stops with a report if a scenario is infeasible for all pilot seeds; (b) **technical failure** (a run is missing or incomplete because of a crash or interruption): the run is recomputed (jobs are deterministic); only if it cannot be recomputed is the seed excluded for all algorithms and listed; (c) **algorithmic failure** (an algorithm returns an empty or unusable set although the instance is feasible): never excluded; the outcome HV = 0 is recorded and counted. By construction the restricted decoder never returns a forbidden team, so (c) can only arise from an implementation error and would be reported as a defect.
